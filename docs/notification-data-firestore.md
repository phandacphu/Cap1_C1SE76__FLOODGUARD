# FLOODGUARD - Notification Data in Firestore

## Jira Task

CCF-148 - NOTI-DB-01 - Implement Notification Data in Firestore

## Purpose

Implement the Firestore data layer for notifications.

This task does not implement FCM delivery, automatic
notification triggers, or public Notification APIs.

## Firestore Collection

Collection: notifications

Document path: notifications/{notificationId}

The document ID is generated by Firestore.

## Notification Schema

| Field          | Type              | Description                |
| -------------- | ----------------- | -------------------------- |
| recipientId    | string            | User document ID           |
| type           | string            | Notification type          |
| title          | string            | Notification title         |
| body           | string            | Notification message       |
| relatedEntity  | object            | Related SOS or flood alert |
| createdAt      | Timestamp         | Creation time              |
| readAt         | Timestamp or null | Read time                  |
| deliveryStatus | string            | Delivery state             |
| retryCount     | number            | Delivery retry count       |
| lastAttemptAt  | Timestamp or null | Last delivery attempt      |
| nextRetryAt    | Timestamp or null | Next scheduled retry       |

## Supported Notification Types

- flood_warning -> flood_alert
- sos_status -> rescue_request

relatedEntity contains:

- type: related entity type
- id: related document ID

## Initial Values

When creating a notification:

- createdAt = serverTimestamp()
- readAt = null
- deliveryStatus = pending
- retryCount = 0
- lastAttemptAt = null
- nextRetryAt = null

Delivery states planned for future tasks:

- pending
- sent
- failed

CCF-148 initializes deliveryStatus only.
Delivery transitions and retries are not implemented here.

## Implemented Service Functions

File: backend/src/services/notification.service.js

- normalizeNotificationData(data)
  Validates and normalizes notification input.

- createNotification(data)
  Creates a notification in Firestore.

- getNotificationById(notificationId, recipientId)
  Reads a notification and checks recipient ownership.

- getNotificationsByRecipient(recipientId)
  Lists notifications for one recipient, newest first.

- markNotificationAsRead(notificationId, recipientId)
  Uses a Firestore transaction to set readAt.

## Validation

- recipientId must be a valid Firestore document ID.
- type must be flood_warning or sos_status.
- title and body must be non-empty strings.
- relatedEntity must match the notification type.
- relatedEntity.id must be a valid document ID.
- Document IDs cannot be empty, "." or "..".
- Document IDs cannot contain "/" or exceed 1500 UTF-8 bytes.
- Document IDs cannot match the reserved pattern `__.*__`.

## Security Notes

- Ownership is checked in the service for reading
  individual notifications and marking them as read.
- Callers must obtain recipientId from a trusted,
  authenticated user context.
- No public Notification API is implemented in this task.
- Existence of recipient and related entity documents
  is not verified by the current service.
- Firebase Admin SDK bypasses Firestore Security Rules.
- Firestore Security Rules have not been modified here.
- No FCM tokens or credentials are stored in notifications.

## Limitations

- Real Firestore integration has not been tested.
- No push notification is sent.
- No notification trigger service is implemented.
- No delivery retry or failure-handling logic exists.
- No Notification HTTP endpoints are provided.
- Recipient queries have no pagination.
- Recipient list sorting happens in memory.
- No Firestore TTL policy is configured.
- No Firestore index configuration was changed.
