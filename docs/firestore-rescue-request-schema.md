\# Firestore Rescue Request Schema



\## Jira Task



\- ID: CCF-73

\- Task: SOS-DB-01 - Implement Rescue Request Data in Firestore



\## Collection



```text

rescue\_requests/{requestId}

```



This collection stores SOS rescue requests submitted by residents.



\## Fields



| Field | Type | Required | Description |

|---|---|---:|---|

| `residentId` | string | Yes | Firestore document ID of the resident who submitted the SOS request |

| `location.latitude` | number | Yes | SOS latitude, from -90 to 90 |

| `location.longitude` | number | Yes | SOS longitude, from -180 to 180 |

| `urgency` | string | Yes | `low`, `medium`, `high`, or `critical` |

| `numberOfPeople` | integer | Yes | Number of people needing support; must be at least 1 |

| `note` | string or null | No | Additional information from the resident |

| `status` | string | Yes | Initial value is `submitted` |

| `createdAt` | Firestore Timestamp | Yes | Server creation time |

| `updatedAt` | Firestore Timestamp | Yes | Server update time |

`createdAt` and `updatedAt` are generated by the backend with Firestore server timestamps.



\## Status Lifecycle



The initial status of a newly created SOS request is:



```text

submitted

```



The later rescue workflow is planned to use:



```text

submitted -> received -> in\_progress -> assisted

```



A request may also be:



```text

cancelled

```



Status transition history will be implemented separately in CCF-74.



\## Relationship



`residentId` references:



```text

users/{residentId}

```



A resident may create multiple rescue requests over time.

\## Prototype Data Notice



Rescue request records used for development and demonstration are sample or simulated data. They must not be presented as official emergency dispatch information.
