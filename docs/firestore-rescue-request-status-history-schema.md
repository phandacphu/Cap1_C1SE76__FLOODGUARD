\# Firestore Rescue Request Status History Schema



\## Jira Task



\- ID: CCF-74

\- Task: SOS-DB-02 - Implement SOS Status History Data in Firestore



\## Collection



```text

rescue\_request\_status\_history/{historyId}

```



Each document records one SOS status history entry.



\## Fields



| Field | Type | Required | Description |

|---|---|---|---|

| requestId | string | Yes | Referenced document ID in rescue\_requests |

| oldStatus | string or null | Yes | Previous status; null for the initial entry |

| newStatus | string | Yes | Status recorded by this entry |

| changedBy | string | Yes | ID of the user responsible for the change |

| changedAt | Firestore Timestamp | Yes | Server-generated recording time |

| note | string or null | No | Optional explanation |



\## Supported Statuses



\- submitted

\- received

\- in\_progress

\- assisted

\- cancelled



\## Validation



\- requestId and changedBy must be non-empty strings.

\- The referenced rescue request must exist.

\- oldStatus and newStatus must use supported status values.

\- A missing oldStatus is normalized to null.

\- When oldStatus is null, newStatus must be submitted.

\- oldStatus and newStatus must differ.

\- note must be a string or null.

\- changedAt is generated by the backend.



The current service does not verify whether changedBy references

an existing user or whether that user has permission to change status.



\## Example Initial Entry



```json

{

&#x20; "requestId": "ccf73-sample-rescue-request-01",

&#x20; "oldStatus": null,

&#x20; "newStatus": "submitted",

&#x20; "changedBy": "ccf73-sample-resident-01",

&#x20; "note": "SOS request submitted"

}

```



changedAt is added as a Firestore server timestamp.



\## Service Functions



\- createRescueRequestStatusHistory: creates an entry with an automatic ID.

\- getRescueRequestStatusHistoryById: retrieves an entry or returns null.

\- setRescueRequestStatusHistoryById: writes a fixed-ID sample entry.

\- normalizeRescueRequestStatusHistoryData: validates and normalizes input.



The fixed-ID helper overwrites an existing entry and its changedAt value.

It is intended for preparing demo/test data, not editing operational history.



\## Scope and Consistency



CCF-74 provides data storage and validation only.



Writing a history entry does not update the status in rescue\_requests.

The service does not enforce a transition sequence or compare oldStatus

with the current request status.



The future status-update API must:

\- identify the acting user from authentication;

\- check permissions and allowed transitions;

\- update the request and append its history in one atomic operation.



\## Prototype Data



Sample entries are simulated data for development and testing.

Sample actor IDs may not reference actual users.

They must not be presented as real rescue activity.
